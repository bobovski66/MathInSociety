Week 10 / AI and computation

How many possibilities must a program examine?

A short sequence of yes-or-no decisions can create many possible outcomes. This activity explores the amount of work involved in looking through them, and how a constraint reduces the search.

A program that checks every possible answer

Think about a service computer choosing whether to send each of several alerts. For every alert, the decision is 0 (do not send) or 1 (send). If there are four alerts, a possible plan might be 0101. The program could inspect all sixteen four-bit plans and score each one.

This is a simple example of exhaustive search: check each possible candidate, calculate its score, and keep the best one. The rule is easy to describe. But the amount of work grows quickly if the program examines every string.

This is one way computational complexity matters in software and some AI systems. The number of possibilities grows as \(2^n\) when there are \(n\) independent yes-or-no choices. Real systems may use much better methods than inspecting everything; the comparison helps us understand why more efficient methods are valuable.

A rule that excludes some plans

Suppose two neighboring alerts cannot both be sent. In binary, that means a code cannot contain 11. You saw this same kind of restriction in Week 9. Our complete search would no longer need to consider every possible binary string.

One way to count the allowed strings is to group them by their last digit. A legal code ending in 0 can follow any legal shorter code. A legal code ending in 1 must have a 0 before that last 1. These cases lead to a recursive count:

\[a_n=a_{n-1}+a_{n-2}.\]

The sequence begins 2, 3, 5, 8 when \(n=1,2,3,4\). This is a different recurrence from simply doubling. It appears because the restriction changes which choices are possible.

What this says—and what it doesn't

Many computational systems solve problems by searching, comparing, and filtering possible answers. Some AI systems do related work on far larger and more sophisticated representations. But not every AI system is a binary decision tree, and the patterns here do not prove that an AI model is chaotic or fractal.

What the exercise demonstrates is a measurable source of computational difficulty: the number of possible candidates can grow rapidly with the number of choices. A constraint may reduce that number, but only if it faithfully represents the problem.
