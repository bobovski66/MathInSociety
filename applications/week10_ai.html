Module 10: AI Application — Autoregression, Branching, and Prediction

Recursion and probability come together in step-by-step text generation.

A question for this module
Why can one small early word change the entire rest of an AI-generated response?

By now you have most of the pieces. Text became tokens. Tokens led to next-token probabilities. Attention combined context. Information measured surprise. Now recursion tells us how one local prediction becomes a whole paragraph.

Start with familiar mathematics

The Module 10 idea

In Module 10, a recursion such as \[ x_{n+1}=rx_n(1-x_n) \] uses the current state to produce the next state. Repeating the rule produces a trajectory. You also saw that long-term behavior can become difficult to predict when small differences are repeatedly carried forward.
Now put that mathematics to work

The AI connection

A language model generates one token, appends it to the text, and then uses the enlarged text to compute a new next-token distribution. This repeated process is called autoregressive generation. Unlike the deterministic logistic-map examples, text generation can also involve probabilistic sampling. Two runs can therefore take different branches even when they begin with the same prompt.
Keep the scale in perspective. These numbers are deliberately small so the calculation is visible. A real LLM uses a much larger vocabulary, high-dimensional vectors, and many repeated layers. We are isolating one genuine mathematical structure at a time.
Follow one example

Work through the calculation

Suppose the current prompt is:
The light in the forest was …
and the next-token distribution is \[ P(\text{moving})=0.45,\quad P(\text{flickering})=0.35,\quad P(\text{Venus})=0.20. \] If “moving” is selected, the next calculation uses a context ending in “was moving.” If “Venus” is selected, the next calculation uses a different context ending in “was Venus.” One early choice therefore changes the input to every later step. The model does not first write a hidden complete paragraph and then reveal it. The text is built recursively, token by token.

Where this leaves us
The full thread of these applications can now be read as \[ \text{text} \to \text{tokens} \to \text{probabilities} \to \text{weighted context} \to \text{information} \to \text{new text}, \] with the output becoming part of the next input. That does not explain every engineering detail of a modern LLM. It does give you a real mathematical skeleton for thinking about one.
