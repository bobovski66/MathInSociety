Week 5 Application — A Radio Sensor Packet

Design and check a small binary message sent by a remote environmental sensor.

How to complete this application

  1. Build the message in transmission order: status code, parity, stored measurement, then alarm information.
  2. Count 1s explicitly when choosing or checking an even-parity bit.
  3. Keep compression and parity conceptually separate: one removes redundancy; the other intentionally adds redundancy for error detection.

Math model

Eight states need 3 bits because \(8=2^3\). Even parity makes the total number of 1s even. If \(p=1/2^k\), the information content is \(k\) bits.

Context

A sensor has to communicate reliably with very few bits

A remote water-quality station sends a short status message by radio once each minute. The station has 8 possible operating states, numbered 0 through 7. A status number is encoded in binary. The station then appends one even parity bit, chosen so the complete transmitted block contains an even number of 1s.

The station also records temperature to the nearest tenth of a degree. Because a tenth, 1/10, does not have a finite binary representation, the device stores temperature as an integer number of tenths of a degree. For example, 23.7°C is stored as the integer 237.

Finally, a severe alarm occurs on only about 1 out of 64 minutes. Information content measures how surprising that outcome is.

Investigation

Build the message

1. Status encoding

How many binary digits are required to distinguish 8 possible states?

If the station is in state 5, write 5 as a 3-bit binary code.

2. Add even parity

State 5 is encoded as 101. It currently contains two 1s.

3. Check a received message

The receiver gets 1110. Under even parity, should the receiver flag this block as containing an error?

4. Store a decimal measurement

The station measures 18.4°C. It stores tenths of a degree as an integer.

5. Information in the rare alarm

The severe alarm occurs with probability 1/64 = 1/2⁶.

6. A short repeated transmission

Over ten minutes the status summary is NNNNNNNNAA, where N means normal and A means alarm. Using run-length encoding, enter the compressed form.
