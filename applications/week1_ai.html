Step 1 · Module 1 mathematics

Sequences really do care about order

In Module 1, you worked with sequences and recursion. For example,

\[5,8,11,14,\ldots\]

is an arithmetic sequence. If we begin with \(a_0=5\), then

\[a_n=5+3n\qquad\text{and}\qquad a_{n+1}=a_n+3.\]

The important idea here is that a sequence is ordered: first term, second term, third term, and so on.

Step 2 · Make the AI connection

Now let text become a sequence

A computer needs a numerical representation of text. An LLM first breaks text into pieces called tokens. A token may be a whole word, part of a word, punctuation, or another short text fragment. Each token gets an integer label called a token ID.

The ID is only a label. Bigger ID numbers do not mean “later in the sentence” or “more important.” Here is a tiny made-up vocabulary, deliberately listed in numerical order:

Token IDToken
8on
17sat
42cat
55the
91mat
103slept

Using the table,

\[(42,17,8,55,91)\]

decodes to “cat sat on the mat.” The sentence determines the order; the numbers only identify the tokens.

Step 3 · Worked example

The arithmetic progression hiding in generation

Suppose a prompt starts with 4 tokens and the model adds exactly one new token on each generation step.

Step \(n\)Number of tokens \(L_n\)
04
15
26
37

The length follows the arithmetic sequence

\[L_n=4+n,\]

or recursively,

\[L_{n+1}=L_n+1.\]

The token IDs themselves do not form an arithmetic progression. The number of tokens does, because one token is appended each step.

What to carry forward

The AI idea of this module

Module 1 gives us the first piece of the LLM story:

\[\text{text}\longrightarrow\text{an ordered sequence of numbered tokens}.\]

Once text is represented as a sequence, a model can repeatedly append a new token. That is already a recursive process.

These examples are intentionally small. Real LLMs use much larger numerical objects and many repeated layers, but the mathematical structure highlighted here is genuine.
