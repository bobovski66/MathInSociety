Step 1 · Module 2 mathematics

Outcomes and probabilities

In Module 2, you learned to turn counts into relative frequencies and recognize a probability distribution. If 100 observations fall into four categories with counts \[ 50,25,20,5, \] then their relative frequencies are \[ 0.50,0.25,0.20,0.05. \] They are all nonnegative and add to 1, so they form a probability distribution. The names of the categories do not matter to the mathematics.
Step 2 · Make the AI connection

For an LLM, the categories can be possible next tokens

Suppose the current text is:
“The cat slept on the …”
A tiny language model might assign:
Possible next tokenProbability
bed0.50
sofa0.25
floor0.20
moon0.05
This is the same kind of mathematical object from Module 2: categories with probabilities totaling 1. The model can then sample from this distribution. The highest-probability token is favored, but it does not have to be chosen every time.

Keep the scale in perspective: this page uses tiny numbers so you can see the mathematics. Real language models use many-dimensional vectors, very large vocabularies, and many repeated layers. The simplified calculation is a model of one mathematical structure, not a miniature copy of the whole system.

Step 3 · Worked example

Use complements and expected counts exactly as before

From the table, \[ P(\text{bed})=0.50. \] So \[ P(\text{not bed})=1-0.50=0.50. \] If this exact distribution were sampled 200 independent times, the expected number of “sofa” selections would be \[ 200(0.25)=50. \] That does not mean exactly 50 must occur in every batch of 200. It is a long-run expectation, just like the probability calculations in this module.

The AI idea of this module
